# 虚拟博物馆展厅平台设计文档

## 1. 项目概述

### 1.1 项目目标
创建一个纯前端的虚拟博物馆展厅平台，用户无需编程即可创建、自定义并分享 3D 虚拟展厅。支持上传展品图片、拖拽布展和 AI 辅助布局，生成可漫游的沉浸式链接。

### 1.2 核心特性
- **纯前端实现**：仅使用 HTML + CSS + JavaScript，无后端依赖
- **零编程门槛**：可视化操作，无需代码知识
- **3D 沉浸式体验**：基于 Three.js 的 3D 场景渲染
- **第一人称漫游**：WASD 移动 + 鼠标拖拽视角
- **URL 分享**：展厅数据编码到 URL 哈希中

---

## 2. 功能需求

### 2.1 展厅创建
- 用户从 3 种预设模板中选择：
  - **古典博物馆风格**：暖色调墙面、木质展柜、柔和灯光
  - **现代美术馆风格**：白色墙面、轨道射灯、简洁展台
  - **历史考古风格**：深色墙面、玻璃展柜、重点照明

### 2.2 展品管理
- **上传展品**：支持 JPG/PNG 格式图片
- **展品信息**：名称、描述、尺寸（用于自动缩放）
- **展品类型**：
  - 墙面挂画：悬挂在墙面上
  - 展台陈列：放置在独立展台上

### 2.3 布局编辑
- **AI 辅助布局**：
  - 自动分析展品数量和尺寸
  - 智能分配到墙面和展台位置
  - 保持视觉平衡和参观动线合理
- **手动拖拽编辑**：
  - 拖拽调整展品位置
  - 旋转展品角度
  - 缩放展品大小
  - 删除展品

### 2.4 漫游体验
- **控制方式**：
  - WASD 键盘移动
  - 鼠标拖拽旋转视角
  - 滚轮缩放（可选）
- **碰撞检测**：防止穿墙和穿展品
- **展品交互**：走近展品时显示信息卡片

### 2.5 分享功能
- **数据编码**：将展厅配置（展品位置、信息、模板选择）编码为 JSON
- **URL 哈希**：使用 LZ-String 压缩后编码到 URL 哈希部分
- **分享链接**：生成完整 URL，他人打开即可漫游

## 3. 技术架构

### 3.1 技术栈
| 组件 | 技术选型 | 说明 |
|------|----------|------|
| 3D 引擎 | Three.js r150+ | 3D 场景渲染 |
| UI 框架 | 原生 JavaScript | 无框架依赖 |
| 样式 | 原生 CSS | 无预处理器 |
| 数据压缩 | LZ-String | URL 数据压缩 |
| 存储 | LocalStorage | 本地草稿保存 |

### 3.3 数据模型

```javascript
// 展厅配置结构
interface ExhibitionConfig {
  template: 'classical' | 'modern' | 'archaeological';
  exhibits: Exhibit[];
  cameraStart: Vector3;
}

// 展品数据结构
interface Exhibit {
  id: string;
  type: 'wall' | 'pedestal';
  image: string;           // Base64 或 URL
  name: string;
  description: string;

  rotation: Vector3;
  scale: Vector3;

```

## 5. 核心算法

### 5.1 AI 布局算法
```
输入：展品列表（含类型和尺寸）
输出：展品位置配置

1. 分析展品数量和类型比例
2. 计算可用墙面面积和展台数量
3. 墙面展品布局：
   - 按高度分组（大展品在上，小展品在下）
   - 保持水平间距均匀
   - 避免遮挡
4. 展台展品布局：
   - 沿参观动线分布
   - 重要展品放在视觉焦点
5. 输出最终位置配置
```

### 5.2 URL 编解码
```
编码流程：
1. 展厅配置对象 → JSON.stringify()
2. JSON 字符串 → LZ-String.compress()
3. 压缩数据 → Base64 编码
4. Base64 → URL 安全编码
5. 附加到 URL 哈希：#data=xxx

解码流程：
1. 读取 URL 哈希参数
2. URL 安全解码 → Base64 解码
3. LZ-String.decompress() 解压
4. JSON.parse() 还原配置
```

## 6. 错误处理

### 6.1 图片上传
- 格式检查：仅允许 JPG/PNG
- 大小限制：单张图片最大 5MB
- 加载失败：显示占位图和错误提示

### 6.2 URL 解码
- 哈希不存在：显示默认展厅或提示
- 解码失败：显示错误信息和返回首页选项
- 数据损坏：尝试恢复部分数据

### 6.3 本地存储
- Storage 满：提示用户清理或导出
- 浏览器不支持：降级为仅 URL 分享

## 7. 性能优化

### 7.1 图片处理
- 上传时自动压缩到合适分辨率
- 使用 WebP 格式（如支持）
- 懒加载远处展品纹理

### 7.2 3D 渲染
- 限制同时渲染的展品数量
- 使用 LOD（Level of Detail）
- 遮挡剔除

### 7.3 URL 长度
- URL 哈希长度限制约 2000 字符
- 超过限制时提示用户导出文件
- 使用高效压缩算法

## 10. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| URL 长度限制 | 无法分享大型展厅 | 提供导出文件备选方案 |
| 图片加载慢 | 用户体验差 | 压缩和懒加载 |
| 移动端性能 | 帧率低 | 降低渲染质量，限制展品数 |
| 浏览器兼容性 | 部分功能不可用 | 降级方案和提示 |
